# Employee Payroll System

A Python and FastAPI learning project for managing employee records, tracking Active/Inactive status, and calculating monthly payroll. Employee information is persisted in a local CSV-formatted text file (`employees.txt`), while payroll history is held in memory for the current server session.

## Problem Statement

Manually maintaining employee details, employment status, and monthly salary calculations can be time-consuming and error-prone. This project provides a small web application to add employees, preserve employee details between restarts, toggle employee status, calculate gross and net salary, and inspect payroll calculations from the current session.

## Objectives

1. Practise Python programming through a practical application.
2. Build web routes and form handling with FastAPI.
3. Store employee records in a local file without requiring an external database.
4. Preserve Active/Inactive status and joining dates across restarts.
5. validate monetary inputs and handle common errors.
6. Expose selected information through JSON API endpoints.

## Features

- Employee creation with an automatically assigned employee ID.
- Employee details: name, department, role, basic salary, joining date, and status.
- Employee data saved to `employees.txt`.
- Active/Inactive status toggle; inactive employees are retained rather than deleted.
- Only active employees can be selected for new payroll calculations.
- Payroll calculator for basic salary, allowances, bonus, deductions, gross salary, and net salary.
- Input validation for monetary values and payroll month.
- Dashboard with employee counts and current-session payroll summaries.
- Employee directory and payroll history pages.
- JSON endpoints for employees and payroll history.
- Interactive API documentation generated by FastAPI.

## Workflow

### Employee workflow

1. Open the application dashboard.
2. Choose **Add Employee**.
3. Enter the employee name, department, role, and monthly basic salary.
4. Submit the form.
5. FastAPI validates the form and creates an `Employee` object.
6. The application saves the employee list to `employees.txt`.
7. The employee appears in the employee directory.
8. Use **Deactivate** or **Reactivate** to update the employee's status.
9. The updated status is saved and loaded on the next application startup.

### Payroll workflow

1. Open **Calculate Payroll**.
2. Select an active employee.
3. Choose the payroll month.
4. Enter allowances, bonus, and deductions.
5. The application validates the month and monetary values.
6. The calculator computes gross salary and net salary.
7. A payroll record is added to the in-memory history.
8. The result is displayed and is available in payroll history and the payroll-history API for the current session.

## Installation and Execution

Commands below assume the terminal is opened in the project directory—the directory containing `main.py` and `employee_storage.py`.

### 1. Create and activate a virtual environment (Windows PowerShell)

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
```

If PowerShell blocks activation, you can run Python using the environment directly:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m uvicorn main:app --reload
```

### 2. Install dependencies

```powershell
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

If `requirements.txt` is not yet populated, install the minimum packages used by this application:

```powershell
python -m pip install fastapi "uvicorn[standard]" python-multipart
```

`python-multipart` is required by FastAPI when using `Form(...)` form parameters.

### 3. Run the application

```powershell
python -m uvicorn main:app --reload
```

The command uses `main.py` as the Python module and `app` as the FastAPI object defined inside it.

Open these local addresses in a browser:

- Application: `http://127.0.0.1:8000/`
- Interactive API documentation: `http://127.0.0.1:8000/docs`
- Alternative API documentation: `http://127.0.0.1:8000/redoc`

Stop the development server with `Ctrl+C`.

### 4. Common commands

```powershell
# Check Python version
python --version

# Install dependencies
python -m pip install -r requirements.txt

# Start the app
python -m uvicorn main:app --reload

# Start on a different port
python -m uvicorn main:app --reload --port 8001

# Check installed packages
python -m pip list

# Save installed packages to requirements.txt (optional)
python -m pip freeze > requirements.txt
```

## API Endpoints

### `GET /api/employees`

Returns employee data as JSON, including employee ID, name, department, role, basic salary, joining date, and active status.

Example response:

```json
[
  {
    "id": 1,
    "name": "Example Employee",
    "department": "Finance",
    "role": "Analyst",
    "monthly_basic": "30000.00",
    "joined_on": "2026-01-15",
    "active": true
  }
]
```

This is an illustrative response; the actual values depend on the local employee file.

### `GET /api/payroll/history`

Returns payroll calculations made during the current server session, including the payroll ID, employee name, month, salary components, and timestamp.

Example response:

```json
[
  {
    "payroll_id": 1,
    "employee_name": "Example Employee",
    "month": "2026-10",
    "basic": "30000.00",
    "allowances": "5000.00",
    "bonus": "2000.00",
    "gross": "37000.00",
    "deductions": "3000.00",
    "net": "34000.00",
    "created_at": "2026-10-27T10:30:00"
  }
]
```

This example is illustrative. Payroll history is not persisted and will be empty after restarting the application.

## Payroll Formula

```text
Gross Salary = Basic Salary + Allowances + Bonus
Net Salary   = Gross Salary - Deductions
```

The application uses `Decimal` with two decimal places and `ROUND_HALF_UP` rounding for monetary values. It rejects invalid or negative amounts and rejects deductions greater than gross salary.

## Data Storage

### Employee records

`employee_storage.py` uses `csv.DictReader` and `csv.DictWriter` to read and rewrite employee records. The file path is built relative to the Python module using `Path(__file__).with_name("employees.txt")`, so the storage file is located alongside `employee_storage.py`.

The stored fields are:

```text
employee_id, name, department, role, salary, active, joined_on
```

The file is CSV-formatted despite the `.txt` extension. The storage helper tolerates malformed rows by skipping rows it cannot parse. Older five-column records are intended to default to Active status and an empty joining date.

### Persistence summary

| Data | Storage | Survives restart? |
|---|---|---|
| Employee details | `employees.txt` | Yes |
| Employee Active/Inactive status | `employees.txt` | Yes |
| Employee joining date | `employees.txt` | Yes |
| Payroll history | In-memory Python list | No |
| Payroll ID counter | In-memory variable | No |

**Important implementation note:** `main.py` loads employees from the file when the module starts, then calculates the next employee ID from the highest saved ID. Payroll history and its ID counter are initialized in memory.

## Validation and Error Handling

The application includes several basic safeguards:

- Required employee form fields.
- Stripping leading and trailing spaces from employee text fields.
- Duplicate-name check for active employees.
- Monetary input conversion and validation.
- Rejection of negative amounts and non-finite decimal values.
- Rejection of deductions greater than gross salary.
- Payroll month parsing using the `YYYY-MM` format.
- Rejection of payroll requests for missing or inactive employees.
- HTTP 404 for an unknown employee ID when toggling status.
- HTML escaping for dynamic text displayed in pages.
- Skipping malformed employee records during file loading.

## Limitations

- Payroll records are held in memory and disappear on restart.
- Employee data is stored in a local file, not a database.
- There is no authentication or role-based authorization.
- The application is intended for learning and demonstration, not production payroll processing.
- Payroll calculations do not implement country-specific tax, benefits, or statutory deduction rules.
- A local file is not ideal for concurrent writes or multi-user deployments.
- The duplicate check uses active employee names rather than a dedicated unique identifier such as an email address.
- The current HTML forms use standard form submissions and redirects rather than live AJAX updates.
